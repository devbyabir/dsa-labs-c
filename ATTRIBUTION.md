# Provenance and attribution

## Available records

The maintainer's second-semester DSA submissions at Zhengzhou University (2024)
are the recovery source for these exercises. The tracked source headers and Git
history identify lab names and later changes, but do not identify the original
author or upstream URL of every inherited implementation.

| Files | Recovery source | Attribution status |
| --- | --- | --- |
| Labs 1–3 and 5 | Text in submitted Word lab reports | Original sources of inherited fragments not established |
| Lab 4 and labs 6–11 | Submitted source archives | Original sources of inherited fragments not established |
| Later input checks, cleanup, tests and tooling | Repository revision history | Changes recorded in Git; this does not establish ownership of earlier code |

The archive labelled Lab 5 contained Lab 10; the expression-tree implementation
was recovered from the Lab 5 report instead. Teacher answer files, lecture examples,
reports, screenshots and student IDs are not included.

## Reuse status

See [LICENSE.md](LICENSE.md). No blanket license is asserted for the recovered
code. Algorithm names identify methods, not authorship of a particular implementation.

When an upstream source is identified, record its exact URL, author, affected files
and applicable license, retaining any required notices. Do not invent attribution
or apply a repository-wide permissive license without resolving the inherited
material's status. Corrections to provenance can be submitted through an issue or PR.
